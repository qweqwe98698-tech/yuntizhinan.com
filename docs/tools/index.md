# 实用工具箱：自查方法合集

与其到处提问「我的网络怎么了」，不如先花几分钟自查。这一页汇总五类可以立刻上手的检测方法，全部只需浏览器或系统自带命令，不依赖特定软件。

## 查出口 IP

打开任意 IP 查询网站，看到的地址就是你当前的出口 IP。开关代理各查一次：两次结果不同说明代理生效；显示的地区应与所选节点一致，若不一致可能是节点落地与标称不符。注意部分查询站对同一 IP 的归属地判定并不一致，以多个来源交叉验证为准。

## DNS 泄漏自查

代理生效不等于 DNS 查询也走了代理——如果域名解析仍由本地运营商完成，访问记录依然可能暴露。自查思路是使用 DNS 检测页面查看解析服务器归属：出现本地运营商的服务器即存在泄漏。完整步骤与修复方法见 [DNS 泄漏检测教程](/troubleshooting/dns/dns-leak-test/)，相关背景知识在 [DNS 问题专栏](/troubleshooting/dns/)。

## 延迟与丢包测试

用系统自带的 ping 命令连续发包，观察平均延迟与是否丢包；需要定位问题发生在哪一跳时，用 mtr（Windows 可用 pathping）查看逐跳的延迟与丢包分布。测试要覆盖不同时段——晚高峰的数据才最能反映真实体验。命令示例与结果解读见[丢包诊断指南](/troubleshooting/speed/packet-loss-diagnosis/)。

## 订阅流量查询

多数服务商在用户面板显示已用流量与重置日期，部分客户端也会在订阅信息中同步展示。速度突然变慢时先确认流量是否用尽或被限速，这是最容易被忽略的原因之一。订阅无法更新时参考[订阅导入失败的处理](/troubleshooting/login/subscription-import-failed/)。

## 系统时间校准

部分代理协议的握手过程对时间敏感，设备时间偏差过大可能导致所有节点无法连接。检查系统是否开启了自动同步时间，手动改过时区的设备尤其要留意。想了解哪些协议受影响，可阅读[协议知识总览](/protocols/)。
