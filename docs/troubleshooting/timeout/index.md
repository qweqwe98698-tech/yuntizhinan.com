# 所有节点都超时？按这个顺序排查最省时间

所有节点同时超时，最常见的原因是订阅已过期或流量用尽，其次是本地网络阻断了代理流量。第一步先登录机场官网确认套餐状态，再手动更新一次订阅。

## 故障表现

- 客户端内做延迟测试，所有节点显示 Timeout、超时或 -1；
- 切换任意地区、任意协议的节点，网页都无法打开；
- 此前使用正常，某天起突然全部失效，期间没有改过任何设置；
- 更新订阅后问题依旧，或订阅本身也无法更新。

如果只有个别节点超时、其余可用，那属于单节点故障，切换节点即可，不必走完本文流程。症状与此都不符的，可回[故障排查中心](/troubleshooting/)按症状重新定位。

## 最常见原因（按概率排序）

1. **订阅过期或流量用尽**。套餐到期或当月流量耗尽后，服务端会拒绝连接，表现为所有节点一起失效。这是最先要排除的一项，登录官网面板即可确认。
2. **本地网络阻断**。校园网、公司网络可能封锁常见代理端口或限制 UDP 流量；家庭宽带在特殊时期也可能出现针对代理流量特征的干扰。
3. **系统时间偏差**。VMess 等协议在握手时校验时间戳，客户端与服务器的时间偏差过大（通常以 90 秒为界）会直接导致认证失败；TLS 证书校验同样依赖准确的系统时间。协议层面的细节可参考 [VMess 与 VLESS 协议说明](/protocols/vmess-vless/)。
4. **防火墙与安全软件拦截**。Windows 防火墙或第三方杀毒软件可能拦截客户端内核进程的联网请求，常见于刚重装客户端或系统大版本更新之后。
5. **客户端配置损坏**。内核异常退出、配置文件残缺、监听端口被其他程序占用，都会让所有节点表现为超时。
6. **机场端故障**。服务器宕机、中转线路中断或入口 IP 被封锁，这类问题往往伴随官网公告或用户群的集中反馈。

## 快速判断方法

用二分法逐层缩小范围，每一步只改变一个变量：

| 步骤 | 操作 | 结果与指向 |
| --- | --- | --- |
| 换节点 | 切换不同地区、不同协议的节点 | 全部超时，说明问题不在单个节点，继续下一步 |
| 换网络 | 从 Wi-Fi 切到手机热点 | 热点下恢复，指向本地网络阻断；依旧超时则继续 |
| 换设备 | 用另一台设备导入同一订阅 | 新设备正常，指向原设备的配置或软件问题 |
| 换客户端 | 换用另一款客户端测试同一订阅 | 新客户端正常，指向原客户端配置损坏；仍超时则机场端故障的可能性上升 |

## 分平台解决步骤

### Windows

1. 打开「设置 → 时间和语言 → 日期和时间」，开启自动同步并手动同步一次；
2. 在 Windows 防火墙和杀毒软件中为客户端主程序及内核进程添加放行规则；
3. 删除旧配置后重新导入订阅；若导入环节本身报错，按[订阅导入失败的处理](/troubleshooting/login/subscription-import-failed/)先解决订阅问题；
4. 仍无效时，参考 [Clash Verge 教程](/tutorials/windows/clash-verge/)重装客户端并从头配置一遍。

### Android

1. 确认系统弹出的 VPN 连接请求已允许，通知栏能看到钥匙图标；
2. 将客户端加入电池优化白名单，防止内核被系统在后台清理；
3. 切到移动数据测试一次，与 Wi-Fi 环境作对照；
4. 长按订阅条目删除后重新导入，并彻底退出客户端再重启。

### iPhone

1. 检查「设置 → 通用 → 日期与时间」是否为自动设置；
2. 确认已允许客户端使用无线局域网与蜂窝网络；
3. 在 Shadowrocket 中删除旧配置后重新添加订阅，具体操作见 [Shadowrocket 使用教程](/tutorials/iphone/shadowrocket/)；
4. 开关一次飞行模式，强制重建网络连接后再测。

## 如何判断是不是机场线路的问题

同时满足以下几条时，问题大概率出在服务商一侧：

- 订阅在有效期内、流量有余量，官网面板显示一切正常；
- 手机热点、第二台设备、第二款客户端都测过，结果仍是全部超时；
- 关闭代理直连访问国内网站正常，说明本地网络本身可用；
- 机场公告或用户群里出现同一时段的集中反馈。

确认之后，短期内能做的主要是等待官方修复；如果类似故障反复出现，可以对照[稳定性优先的机场榜单](/airport/stable/)评估是否更换服务。至于晚高峰变慢、间歇性超时这类症状，更接近线路拥塞而非中断，判断方法见[延迟与丢包诊断](/troubleshooting/speed/packet-loss-diagnosis/)。

## FAQ

**延迟测试全部超时，但网页还能打开，怎么回事？**

延迟测试访问的是客户端设置里的特定测试地址，如果该地址本身不可达或测试方式设置有误，就会出现「测速超时但实际可用」的假象。可在客户端设置中更换测试 URL 后再测一次。

**昨天还正常，今天全部超时，是账号被封了吗？**

先登录官网看套餐状态。这种情况多数是当月流量用尽或入口 IP 被封锁：前者等流量重置或购买加量包，后者等机场更换入口，账号本身被封的情形相对少见。

**换了手机热点还是全部超时，还有必要继续查吗？**

有。热点只排除了原网络的问题，系统时间、防火墙、客户端配置仍可能是根源，建议把分平台步骤走完再下结论。

**Clash 显示已连接但打不开网页，也算这类超时吗？**

不完全一样。节点延迟正常但网页打不开，多与系统代理、分流规则或 DNS 有关，对应的处理流程见 [Clash 已连接但无法上网](/troubleshooting/timeout/clash-no-network/)。
