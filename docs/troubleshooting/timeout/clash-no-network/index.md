# Clash 显示已连接却打不开网页？先看流量有没有进代理

节点测速有延迟、面板一切正常，网页却打不开——最常见的原因是系统代理没有真正生效，流量根本没进 Clash。第一步核对客户端的「系统代理」开关，再用无痕窗口复测。

## 故障表现

- 节点延迟测试有正常数值，并非全部 Timeout；
- 打开任意网页都在转圈或直接报错，或仅境外网站打不开；
- 面板的连接页面几乎没有新记录，流量统计基本不动；
- 换节点、换地区都无效，重启客户端后偶尔短暂恢复。

如果延迟测试本身就全部超时，那是另一类问题，处理路径见[节点全部超时的排查顺序](/troubleshooting/timeout/)；症状都对不上的，可回[故障排查中心](/troubleshooting/)重新定位。

## 最常见原因

1. **系统代理未生效**。开关没打开、被安全软件或其他代理工具改回、代理端口与客户端监听不一致；命令行程序和部分应用默认不读系统代理，还会出现「浏览器能用、软件不行」的组合。
2. **TUN 模式与网卡冲突**。虚拟网卡驱动未装好、服务模式缺失、与其他 VPN 或网游加速器同时运行争抢路由，都会让 TUN 看似开启实则不通。
3. **规则把流量分给了 DIRECT**。订阅自带的规则集缺失或下载失败时，目标域名可能整体落到直连，境外网站自然打不开。
4. **DNS 解析失败**。上游 DNS 不可用、fake-ip 与 redir-host 切换后残留缓存，都会让域名查询卡住，表现和断网很像；各类 DNS 问题的区分见 [DNS 问题总览](/troubleshooting/dns/)。
5. **浏览器代理插件冲突**。SwitchyOmega 一类插件的优先级高于系统代理，情景模式若指向失效端口，就只有这台浏览器上不了网。

## 快速判断方法

- **看连接记录**：访问一个网页，观察面板连接页有没有新条目。完全没有，说明流量没进客户端，查系统代理和插件；有记录但全部标记 DIRECT，查规则；有记录且走了节点却没有数据返回，查节点与 DNS。
- **命令行直连本地端口测试**（端口以客户端实际监听为准）：

```
curl -x http://127.0.0.1:7890 -I https://www.google.com
```

能返回状态码，说明客户端和节点都正常，问题锁定在系统代理或浏览器一侧；不通则继续查客户端内部。

- **无痕窗口复测**：无痕模式停用多数插件，从此恢复正常基本可锁定插件问题。

## 分平台解决步骤

### Windows

1. 在客户端开启「系统代理」，到「设置 → 网络和 Internet → 代理」核对地址与端口是否一致；
2. 使用 TUN 模式前先安装服务模式并以管理员身份运行，同时退出其他 VPN 与加速器；
3. 确认处于规则模式且规则集完整加载，必要时临时切到全局模式验证链路本身；
4. 反复无效时按 [Clash Verge 教程](/tutorials/windows/clash-verge/)重装并从头配置一遍。

### macOS

1. 在「系统设置 → 网络 → 代理」确认 HTTP/HTTPS 代理已被客户端写入；
2. TUN 模式需要授权系统扩展或输入管理员密码，安装后重启一次客户端；
3. 检查是否有别的代理类软件开机自启并覆盖了设置。

### 浏览器与插件

把 SwitchyOmega 等插件切到「系统代理」情景或直接停用；确认浏览器自身的代理设置没被第三方软件锁定。

## 如何判断是不是机场线路的问题

依次确认三件事：全局模式下换过三个以上不同地区的节点、`curl` 经本地端口测试均无响应、连接页能看到走节点的请求却始终没有回包——同时满足时，机场侧故障的可能性明显上升。反过来，只要有一个节点在全局模式下可用，说明链路没问题，回头继续查规则与系统代理。确认线路故障后可关注机场公告等待修复；这类情况频繁出现的话，不妨参考[对 Clash 支持较好的机场](/airport/clash/)评估备选。

## FAQ

**只有部分网站打不开，其余正常，也按本文处理吗？**

不完全是。个别网站打不开更可能与分流规则漏配或解析环节有关，可先把对应域名手动加进代理规则测试，再结合 [DNS 问题总览](/troubleshooting/dns/)排查。

**系统代理和 TUN 需要同时开吗？**

一般不需要。TUN 通过虚拟网卡接管全部流量，覆盖面已包含系统代理的范围；排查问题时建议只保留一种模式，减少变量。

**开代理后国内网站也变慢了，正常吗？**

规则模式下国内域名应命中直连，速度不受影响。若明显变慢，多半是当前处于全局模式，或规则把国内域名也送进了代理。

**订阅更新失败和这个问题有关系吗？**

有可能。规则集与节点信息都来自订阅，订阅残缺会让规则整体失效，处理方法见[订阅导入或更新失败](/troubleshooting/login/subscription-import-failed/)。
