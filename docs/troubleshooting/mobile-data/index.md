# 连 Wi-Fi 正常、切手机流量就断网的原因与解决

Wi-Fi 下一切正常、换成手机流量节点就全部超时，较常见的原因是蜂窝网络的 IPv6-only 与 CGNAT 环境和节点的连接方式不兼容。第一步：换一个走 TCP、以域名方式连接的节点先测一次。

## 故障表现

- Wi-Fi 下代理正常，切到流量后所有节点测速超时或转圈。
- 部分协议的节点在流量下能连，另一部分完全不通。
- 流量下刚开始能用，几分钟后越来越卡直至断开。
- 用手机开热点，共享给电脑后电脑同样无法使用代理。

## 最常见原因（按概率）

**1. 蜂窝网络的 IPv6-only 环境。** 不少运营商的 4G/5G 网络只给设备分配 IPv6 地址，靠 NAT64/DNS64 机制兼容 IPv4 网站——这套机制依赖域名解析。如果节点配置里写的是纯 IPv4 地址，能否连通就取决于系统和运营商是否提供了地址转换（如 464XLAT），条件不满足时连接往往建立不起来。这也是"家里能用、流量不能用"最典型的技术根源。

**2. UDP 流量被运营商 QoS。** Hysteria2、TUIC 等基于 UDP/QUIC 的协议在部分移动网络下会被限速、随机丢包甚至间歇阻断，表现为开头能用、随后卡死。协议特性可参考 [Hysteria2 协议介绍](/protocols/hysteria2/)。

**3. 客户端在蜂窝下的权限与省电限制。** iOS 的 App 无线数据权限若设为"仅 WLAN"，蜂窝下代理直接无法联网；Android 的省流量模式（Data Saver）和激进的省电策略会限制后台流量、杀掉代理进程。

**4. APN 配置异常。** 手动改过 APN、使用物联网卡或定向流量卡时，APN 对应的网络策略可能与普通上网卡不同，部分端口或协议受限的情况并不少见。

**5. 双卡切换后网络栈未刷新。** 切换上网卡后，DNS 与路由信息偶尔仍停留在旧卡的网络上，代理客户端拿着过期的网络接口自然连不上。

## 快速判断方法

1. **开关一次飞行模式。** 强制重新注册网络、重新分配地址，双卡切换类问题多数由此解决。
2. **换协议对比。** 同一机场下分别测 TCP 类节点（Trojan、VLESS over TLS）与 UDP 类节点（Hysteria2）：只有 UDP 类不通，大概率是运营商 QoS。
3. **看客户端日志。** 超时（timeout）多指向网络层不通或被丢弃，拒绝（refused）多指向地址、端口或配置问题。
4. **换卡对照。** 有条件时换另一家运营商的卡测试，可以快速区分是运营商环境还是节点本身的问题。

## 各平台排查步骤

### Windows

电脑通过手机热点上网时，瓶颈在手机侧的蜂窝网络——CGNAT、IPv6 环境会原样传导给电脑，应先按下面的手机步骤处理；同时把电脑客户端的 DNS 改为远程解析，避免本地解析在热点网络下出错，相关知识见 [DNS 问题排查](/troubleshooting/dns/)。

### Android

依次检查：省流量模式中允许代理 App 不受限制；电池优化加入白名单、允许后台运行；订阅里优先选择以域名（而非纯 IPv4 地址）连接的节点。完整配置流程见 [Clash Meta for Android 教程](/tutorials/android/clash-meta/)。

### iPhone

先确认"设置"中该 App 的无线数据权限为"WLAN 与蜂窝数据"，再关闭蜂窝的低数据模式，然后按 [Shadowrocket 配置教程](/tutorials/iphone/shadowrocket/)检查 VPN 配置状态。iOS 特有的细节（描述文件、按需连接、iCloud 专用代理等）在[《iOS 蜂窝数据下节点不可用》](/troubleshooting/mobile-data/ios-cellular/)里有逐项展开。

## 如何判断是不是机场线路的问题

两个信号值得注意：一是节点入口只有纯 IPv4 地址、不提供域名接入，在 IPv6-only 的蜂窝网络下失败概率明显更高，可询问服务商是否支持 IPv6 接入或提供域名入口；二是只有 UDP 类协议在流量下不可用，可请服务商提供 TCP 类协议的备用节点。如果换了域名接入、换了 TCP 协议、换了运营商的卡都不行，而别人用同一节点正常，问题更可能在本机设置。移动场景使用频繁的用户，选服务时可以优先看多协议支持与域名接入能力，参考[稳定线路机场推荐](/airport/stable/)。

## FAQ

**问：为什么手机开热点给电脑，电脑也不能用？**
答：热点共享的正是手机的蜂窝网络，CGNAT、IPv6-only、UDP QoS 这些环境特征会一并传导给电脑，所以要先解决手机侧的连通问题。

**问：定向流量卡、物联网卡为什么问题更多？**
答：这类卡的 APN 和计费策略面向特定业务设计，可能只对白名单内的地址或端口放行，用于代理时受限的概率比普通上网卡高。

**问：信号满格但代理连不上，说明什么？**
答：信号强度只反映与基站的无线链路质量，不代表 NAT、DNS、UDP 策略这些上层环节正常，两者需要分开排查。

**问：蜂窝下需要单独设置 DNS 吗？**
答：一般建议在客户端里启用远程解析或指定可靠的 DNS，避免运营商 DNS64 与客户端本地解析互相干扰；验证方法见 [DNS 泄漏检测](/troubleshooting/dns/dns-leak-test/)。
