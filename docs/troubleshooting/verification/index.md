# 收不到验证码，第一步先确认它从哪条渠道来

验证码走的渠道决定排查方向：邮件类优先翻垃圾箱、换邮箱域名；短信类先确认该服务是否向 +86 号码正常下发；App 内推送类则检查代理有没有把对应应用放进隧道。

## 故障表现

- 注册或登录页提示「验证码已发送」，等了很久收件箱、短信里都没有；
- 反复点击重发，按钮进入更长的冷却倒计时，依旧收不到；
- 部分情况下点了发送后没有任何反馈，页面毫无变化。

最后一种情况要注意：可能是「发送请求」本身没能到达服务器，与网络有关，而不是下发环节的问题。其余症状可回[故障排查中心](/troubleshooting/)重新定位。

## 最常见原因

### 邮件验证码

- 被邮箱判为垃圾邮件，躺在垃圾箱或「订阅/推广」分类里；
- 发件域名被邮箱服务商整体拦截，连垃圾箱都不进——部分国内邮箱对海外自动化邮件的策略较严格；
- 邮箱地址输错一个字符，或注册时用了别名地址；
- 短时间多次触发发送，被服务方限流。

### 短信验证码

- 各服务对 +86 的支持情况不一：有的正常下发、有的延迟明显、少数在注册页就不提供中国区号；
- 国际短信经跨境通道下发，途中可能被运营商的拦截策略误伤；
- 虚拟号码、接码平台的号段容易被识别并拒发；
- 手机端的骚扰拦截应用把验证短信直接归档或删除。

### App 内验证码

Telegram 一类应用会把验证码优先发到已登录的旧设备会话里，而不是短信；如果旧设备离线，或该应用的网络被阻断，验证码就「看起来没发」。分应用代理没有包含对应 App 时，收发都会受影响。

## 快速判断方法

1. 邮件：在收件箱全局搜索发件方关键词，翻遍垃圾箱与所有分类；换 Gmail、Outlook 等国际邮箱再注册一次作对照；
2. 短信：查看拦截记录与黑名单；双卡手机确认验证码发往的是当前在用的号码；
3. App 内：确认旧设备在线且能正常联网，代理规则里放行了该应用；
4. 所有渠道都试过仍无果，且页面点发送毫无反馈，转向网络排查——先换节点再触发一次。

## 分渠道解决步骤

### 邮件类

1. 把发件域名加入白名单后再点重发；
2. 注册一个国际邮箱作为海外服务的专用邮箱，Gmail 注册过程的注意事项见 [Google 服务指南](/software/google/)；
3. 两次发送之间隔开几分钟，连续点击只会延长冷却。

### 短信类

1. 关闭第三方骚扰拦截，检查运营商侧是否开通了拦截服务；
2. 等冷却结束后改用语音来电验证（若页面提供该选项）；
3. Telegram、WhatsApp 的短信问题有单独的处理细节，见[短信验证码专篇](/troubleshooting/verification/sms-not-received/)。

### App 内推送类

1. 找回旧设备并让它保持在线，验证码常出现在旧会话的服务通知里；
2. 代理客户端若开了分应用模式，把目标 App 勾进代理名单；
3. 海外社交类应用的网络要求与常见坑，见[社交软件使用指南](/software/social/)。

## 如何判断是不是机场线路的问题

验证码的下发发生在服务商和运营商一侧，机场影响的主要是两个环节：一是「发送验证码」的请求要经代理送达，节点不通时点了没反应；二是出口 IP 信誉差时，服务方可能静默拒绝下发或要求更多验证。判断方法：换一个不同地区的节点重新触发发送，若立即有了反馈或收到验证码，说明此前的节点环境有问题；长期如此，可考虑[对社交场景更友好的机场](/airport/social/)。

## FAQ

**点了发送，页面提示成功，但就是收不到，问题在哪一环？**

提示成功只代表请求到达了服务方，下发环节仍可能被拦。邮件查垃圾箱与域名拦截，短信查运营商与手机拦截，App 内查旧设备会话。

**换邮箱域名真的有用吗？**

有一定作用。拦截常发生在发件方与收件方域名的组合上，同一封验证邮件发往不同邮箱的到达情况可能完全不同，用国际邮箱做对照能快速定位。

**注册时提示「该号码不可用」，也是收不到的问题吗？**

不是。这是服务方直接拒绝了号码本身，常见于虚拟号段或风控命中，与下发环节无关；换真实手机号或换注册环境再试。

**收到验证码但提交后被拒绝，怎么回事？**

验证码过期、多次请求后旧码失效、出口 IP 触发风控都有可能。用最新收到的一条，并在固定节点上完成整个流程；登录环节的进一步排查见[登录失败排查](/troubleshooting/login/)。
