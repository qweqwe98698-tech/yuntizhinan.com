# ChatGPT 生成中断、提示 Stream Disconnected 的排查与修复

回答输出到一半突然停住，较大概率是代理出口 IP 在会话期间发生了变化，或流式连接被中途回收。先把客户端固定到单一节点并关闭自动切换，刷新页面后点"继续生成"接上。

先用一句话说明原理：ChatGPT 的回答不是整段一次返回，而是通过一条在整个生成期间保持打开的流式长连接（SSE）逐字推送到浏览器——这条连接被任何一环掐断，页面上就表现为输出停住或报错。

## 典型症状

- 回答生成到一半光标停住，等多久都不再继续。
- 页面弹出 Stream Disconnected、Network Error 或红色错误提示框。
- 短回答基本正常，回答越长越容易失败。
- Codex、深度研究（Deep Research）这类长任务运行几分钟后报错退出。

## 可能的原因（按概率从高到低）

**1. 出口 IP 在会话中途变化。** 负载均衡的多出口节点断线重连后会换一个 IP，服务端风控可能把这种变化判定为会话异常并强制断开。这是断流问题里最值得优先排查的一项。

**2. 流式连接被超时回收。** 生成一条长回答需要连接持续保持几十秒到数分钟，而 Codex、深度研究类任务可能要维持更久；只要节点、中转或本地网络对"空闲"连接的超时短于任务时长，就会中途掉线。背后的机制可参考 [WebSocket 连接断开原因总述](/troubleshooting/websocket/)。

**3. 浏览器插件干扰。** 广告拦截、网页翻译、脚本管理类插件可能拦截或改写流式响应，导致输出卡住。这类问题与网络无关，换节点也不会好转。

**4. 客户端自动切换节点。** 自动测速触发切换的瞬间，所有连接重建，正在生成的回答随之中断。

**5. 线路丢包或拥塞。** 高峰期丢包严重时流式传输频繁重传，表现为输出一顿一顿直至断开，可结合[超时类问题排查](/troubleshooting/timeout/)进一步定位。

## 快速判断方法

- **无痕窗口重试。** 无痕模式默认停用多数插件，若从此稳定输出，基本可锁定插件问题。
- **生成前后各查一次出口 IP。** IP 变了，优先处理节点；没变，再看其他方向。
- **观察断点是否集中在相近时长。** 总在差不多的时间断开，指向某处固定超时。
- **换一个单出口节点跑同样的长任务。** 这是区分线路与本地问题最直接的对照实验。

另外，断流后的正确姿势是刷新页面——已生成的内容通常保存在对话里，点击"继续生成"即可从断点续写；避免短时间内反复快速重试，密集重连反而可能触发风控。

## 不同设备上的处理办法

### Windows

在 Clash Verge、v2rayN 等客户端里把策略组固定为手动选择的单一节点，关闭定时测速；浏览器端逐个停用插件复测，必要时清除站点 Cookie 后重新登录。

### Android

固定节点之余，把代理 App 加入电池优化白名单，防止息屏后系统限制后台流量导致隧道中断，设置方法见 [Clash Meta for Android 教程](/tutorials/android/clash-meta/)。

### iPhone

Shadowrocket 保持单节点运行，长任务期间不要在 Wi-Fi 与蜂窝之间切换（切换会重建 VPN 隧道并更换出口路径），配置细节见 [Shadowrocket 使用教程](/tutorials/iphone/shadowrocket/)。

## 怎么确认问题出在机场线路

做一次"单一出口验证"：挑一个标注为单出口或直连落地的节点，任务开始前和结束后各查一次出口 IP，确认全程不变的前提下跑一个长任务。如果这样就稳定，原节点大概率是多出口轮换导致的断流；如果换了单出口节点仍频繁中断，则更可能是丢包、超时等线路质量问题，或本地网络与插件因素。长期跑 AI 长任务的用户，建议选择明确面向 AI 场景优化、出口 IP 稳定的线路（参考 [AI 专用机场挑选思路](/airport/ai/)），各类 AI 工具的访问要点另见 [AI 软件指南](/software/ai/)。

## FAQ

**问：断流后已生成的内容会丢吗？**
答：通常不会。回答内容多数情况下已同步保存到对话记录，刷新页面即可看到，再点"继续生成"接着写即可。

**问：为什么别的网站都正常，只有 ChatGPT 断？**
答：普通网站以短请求为主，断了会自动重试，用户无感知；ChatGPT 的流式输出依赖一条持续保持的长连接，对线路稳定性的要求高得多。

**问：Codex、深度研究类任务对网络有什么特别要求？**
答：这类任务一次运行可能持续十几分钟甚至更久，要求连接全程不断、出口 IP 全程不变，比普通对话严苛，建议专门固定一个稳定的单出口节点来跑。

**问：换了节点还是断，还能查什么？**
答：依次排除浏览器插件（无痕模式验证）、客户端自动切换策略、本地路由器超时，仍无法解决时向服务商反馈断开时间点，请其核查该节点的连接回收策略。
